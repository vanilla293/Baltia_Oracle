# ПРОТОКОЛ БЭКТЕСТА ДУАЛЬНОГО РОУТЕРА (PREDATOR)

Проверяемая система: `oracle.dual_env` (щёлочь/переход/кислота по Хиллу α и
Пригожину φ) + отстранение парламента в кислоте + квантовый триггер +
`execution.plan_exit_fib` / `fib_unit`. Протокол написан под уже существующую
инфраструктуру: тиковая база схемы `recorder.py` (`trades` + `book`),
walk-forward-валидатор `lab/forward_test.py`, калибровка `lab/calibration.py`.

Главный урок прошлых замеров, который протокол обязан не повторить:
**σ была раздута перекрытием окон в √6; заявленные 94% оказались монетой;
экономика умерла на комиссии 5 бп.** Каждый пункт ниже существует, чтобы
такое не прошло второй раз.

---

## 1. Данные: из .txt-логов в каноническую базу

1. Один парсер, одна схема. `.txt`-логи конвертируются в SQLite схемы
   `recorder._SCHEMA` (`trades`: ts_ms, figi, price, qty, side, raw_dir;
   `book`: ts_ms, obi, spread_bps, best_bid/ask, объёмы, levels JSON ≤50 ур.).
   Никаких «пока почитаем прямо из txt» — двойной парсер = двойная правда.
2. Контроль целостности до любого теста: монотонность ts_ms; доля дыр >2с
   ленты; кроссы best_bid ≥ best_ask (выбрасывать кадр, писать счётчик);
   сверка Σqty ленты с дневным оборотом MOEX ISS (расхождение >5% —
   лог бракуется, не «чинится»).
3. Тайм-зоны: всё в UTC мс на входе парсера, конверсия МСК — только там.
4. Каждому прогону — манифест: hash базы, диапазон дат, число сделок,
   инструменты. Результат без манифеста не существует.

## 2. Реплей: событийный, с задержками

1. **Событийный движок, не бары.** Кадр = (тик | снимок стакана). Фичи
   (α Хилла, φ Пригожина, Хоукс n, OBI/CVD/VPIN, Казимир a) считаются
   строго по данным ≤ t. Правило `forward_test.py` («признаки строго до t,
   факт после») — закон.
2. **Задержка решения Δ_dec:** сигнал, посчитанный на кадре t, действует
   на ПЕРВОМ кадре с ts ≥ t + Δ_dec. Свип обязателен:
   Δ_dec ∈ {0, 50, 150, 300, 1000} мс. Эффект, живущий только при Δ=0, —
   артефакт, а не сигнал.
3. **Модель исполнения:**
   - рыночный ордер: проход по уровням L2 снимка на момент t+Δ_dec
     (слиппедж = фактическое поедание глубины), при пустой глубине —
     отказ, не «исполнение по last»;
   - лимитка: очередь. Позиция в очереди = видимый объём уровня на момент
     постановки; исполняется только объёмом ленты, ПРОШЕДШИМ через цену
     после постановки (trade-through), пессимистично: сначала чужая
     очередь, потом мы. «Коснулись цены = исполнились» запрещено — это
     и есть скрытый источник фантомной прибыли лимиточных стратегий;
   - отмена лимитки тоже стоит Δ_dec.
4. **Комиссия:** 5 бп круг (константа стендов `COMMISSION_BPS=5.0`) +
   измеренный слиппедж из модели. Отчёт всегда в NET.

## 3. Walk-forward (роллинг, с чисткой)

1. Разбивка: train-окно W_tr (например, 3 сессии) → **purge-зазор** ≥
   максимального горизонта фич/удержания (600 с) → test-окно W_te
   (1 сессия) → сдвиг на W_te. Никогда не тюнить на данных, которые
   касаются теста даже хвостом окна фичи (утечка через перекрытие —
   уже пойманные грабли).
2. Что пере-калибруется на каждом train (и ТОЛЬКО на нём):
   - `CAL_TABLE` (через `lab/calibration.py`);
   - веса голосов `oracle.calibrate` по trades.jsonl train-периода.
3. Что НЕ фитится нигде (заявлено априори, до прогона): пороги дуальной
   механики α=2/α=3, φ=0.97/0.985, квантовый триггер (0.40/0.95/0.97),
   уровни 0.382/0.618/1.618. Это конвенции — их не оптимизируем, их
   ПРОВЕРЯЕМ. Если хочется подобрать «лучший порог α» — это отдельный
   эксперимент с отдельной поправкой на перебор, не смешивать.
4. Итог — только конкатенация test-окон. Числа с train не публикуются.

## 4. Абляции (без них результат не принимается)

Один и тот же реплей, четыре машины:
- A. **Дуальный роутер** (как реализовано);
- B. **Всегда-парламент** (dual_env отключён, права всегда 1.0) — базовая
  линия «до правки»;
- C. **Всегда-сингулярность** (парламент выключен везде) — проверка, что
  ценность именно в ПЕРЕКЛЮЧЕНИИ, а не в одном из режимов;
- D. **Плацебо-роутер**: те же доли времени в «кислоте», но окна кислоты
  сдвинуты циклически на случайный лаг (детерминированный сид) — убивает
  иллюзию «роутер полезен, потому что просто реже торгует».

Для сетки выхода отдельно: фибо-сетка vs один тейк на 0.618·unit vs один
тейк на 1.618·unit, одинаковые входы. Метрика — net bps и доля исполнений.

## 5. Статистическая честность

1. **Перекрытие:** сделки/сигналы, чьи окна фич или удержания пересекаются,
   не независимы. Кластеризация по дню + **блочный бутстрэп по дням**
   (1000 реплик) для CI; никакой биномиальной σ по перекрывающимся
   наблюдениям (урок √6).
2. **Перебор гипотез:** всё семейство конфигураций (горизонты × пороги ×
   абляции) заранее переписано списком; поправка — SPA Хансена или хотя бы
   Бонферрони по семейству; для доходностей — Deflated Sharpe Ratio.
3. **Минимальные объёмы:** ячейка режима с < 25–30 событиями (стандарт
   стендов `MIN_CELL`) не интерпретируется вообще. Кислота редка — значит,
   вывод по кислоте требует НЕДЕЛЬ данных, а не одной сессии; это пишется
   в отчёт прямо.
4. **Стратификация по среде:** все метрики отдельно для α<2 / 2≤α<3 / α≥3
   (по фактическому α на момент решения). Дуальный роутер — условное
   утверждение; общий средний результат его не подтверждает и не топит.

## 6. Метрики отчёта

- hit-rate по горизонтам 60/180/600 с (сетка `forward_test.py`) с CI
  бутстрэпа; NET bps на сделку и на день;
- Brier + разложение Мерфи (калибровка/разрешение) заявленных вероятностей
  `p_long` — машина обязана оставаться честной, а не только прибыльной;
- MAE/MFE профиль сделок (оценка качества сетки выхода отдельно от входа);
- max drawdown, серия убытков, **α Хилла самого PnL** (если хвост PnL
  тяжелее α=3 — размер позиции пересматривать, см. leverage);
- частота состояний машины (доля времени в кислоте/сингулярности) — дрейф
  частоты между train и test = нестационарность, флаг;
- доля исполненных лимиток сетки и средний недобор (footprint-метрика).

## 7. Критерии приёмки (регистрируются ДО прогона)

1. A превосходит B по NET bps с p<0.05 после SPA/Бонферрони на
   конкатенации test-окон — иначе роутер в прод не идёт (остаётся 🟡).
2. A превосходит D (плацебо) — иначе эффект = «меньше торгуем», а для
   этого роутер не нужен.
3. Выигрыш живёт при Δ_dec ≥ 150 мс.
4. Brier(A) ≤ Brier(B): роутер не должен портить калибровку.
5. В ячейках с n < MIN_CELL — вердикт «данных нет», не «работает».

## 8. Известные ловушки этого конкретного стека (проверять каждый прогон)

- «лучшая цена за 30с» (механика (г) из `entry_probe.py`) — заглядывание в
  будущее, использовать только как потолок, в отчёте помечать;
- `np.roll`-суррогаты для нулей запрещены (шов искажал нуль до 65.8
  перцентильных пунктов — `why_oil`); только циклические сдвиги с
  выбросом шва или IAAFT;
- α Хилла на коротком окне шумит: логировать k (число хвостовых точек);
  k < 10 → α не считается (уже так в `hill_tail`), в реплее НЕ подменять
  последним известным α старше 10 минут — это уже DUMMY;
- симулятор `market_sim.py` пригоден для теста КОНВЕЙЕРА, но не для
  доказательства паттернов (структура эпизодов зашита сидом) — им
  бэктест не заменяется.

⚫ Протокол проверяет машину, а не обещает прибыль. Один прогон одной
сессии — анекдот; закон рынка из него не выводится. 18+.
