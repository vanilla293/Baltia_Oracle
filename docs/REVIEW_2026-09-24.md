# ПИФИЯ 5.3.0 — исправления надёжности и интерфейса

Исходник: `pythia_v5.3.0_a2b8a3a.zip`. Проверка и исправления: 24 сентября 2026 года.

В этом обновлении сохранены торговая стратегия, расчёты, модели и тексты промптов. Основная работа — ошибки при задержках сети, сохранность истории, проверка входных данных и небольшие улучшения интерфейса. Номер приложения оставлен 5.3.0; архив с суффиксом `reviewed` отличает эту сборку от исходной.

## Что исправлено

| Область | Что происходило | Как работает теперь |
|---|---|---|
| Базы SQLite | Любая ошибка инициализации могла привести к удалению базы, WAL и истории. Блокировка или заполненный диск ошибочно считались повреждением. | Автоматическое удаление убрано. Запуск сообщает об ошибке и сохраняет файлы для восстановления. Явная команда сброса работает как раньше. |
| Миграция старой истории | Ошибка добавления `thinking_json` подавлялась без проверки причины. | Наличие колонки проверяется явно; ошибки миграции видны, существующие записи сохраняются. |
| Сбор новостей | Проверка наличия через SELECT и отдельный INSERT оставляли гонку между двумя сборщиками. | Одна атомарная вставка с обработкой конфликта id. Дубли не сбрасывают разметку и релевантность; на новость нужен один SQL-запрос вместо двух. |
| Сохранение ключей | Ошибка поля Telegram могла прийти после сохранения новых DeepSeek/Tinkoff. | Весь запрос проверяется перед единственной записью настроек. Нестроковые токены отклоняются. |
| Сумма миссии | Строковые NaN/Infinity, переполнение и логические значения могли пройти проверку суммы. | Возвращается HTTP 400 до запуска миссии. Пустое поле и ноль сохраняют прежний автоматический режим. |
| Запуск совета/дозора | Между созданием фоновой задачи и регистрацией прогона второй запрос мог быть принят. | Запуск резервируется до первого ожидания. Повторный запрос получает 409; ошибка фонового запуска не маскируется успехом. |
| Завершение сервера | Службы, запущенные при старте, продолжали работать во время закрытия HTTP-соединений. | Сервер хранит эти задачи, отменяет и дожидается их перед закрытием соединений. |
| Свечи | Запоздалый ответ старого интервала мог попасть на новый график. Некорректные OHLC и даты могли ломать отрисовку. | Ответ привязан к инструменту, интервалу и экземпляру графика. Некорректные свечи отбрасываются, дубли времени объединяются. При смене интервала показана загрузка. |
| Медленные запросы | Повторный таймер мог наслаивать запросы; первоначальный вариант защиты свечей мог отбрасывать все медленные ответы. | Одинаковые запросы свечей, цены, статуса и сделок не запускаются параллельно. Медленный ответ свечей остаётся пригодным, запрос вписывания графика сохраняется. |
| Смена миссии | Старые цена, статус и сделки могли обновить экран нового инструмента. Отказ запуска мог создать ложное состояние работающего совета. | Устаревшие ответы игнорируются. При отказе запуска текущая миссия остаётся на экране. |
| Поиск инструмента | Результаты приходили в неправильном порядке или открывали список после его закрытия. Ошибка каталога могла закешироваться как пустой каталог. | Принимается результат актуального запроса; закрытие инвалидирует ожидание. Есть понятные состояния загрузки и ошибки, стрелки, Enter и Escape. |
| Чат | Повторный Enter до ответа POST мог отправить вопрос дважды. История очищается на экране после успеха сервера. Устранены гонки загрузки истории и финального ответа. |

## Визуальные изменения

- Кнопки ключей и настроек помещаются в мобильной шапке. На самых узких экранах сокращается текст логотипа.
- Основная колонка центрируется на широком экране, сохраняя ограничение длины текста.
- Поиск показывает выделенный вариант при управлении с клавиатуры; добавлены ARIA-состояния списка.
- Поле ввода и область сообщений чата корректно сжимаются внутри узкой панели.
- Существующие светлая и тёмная темы, навигация и состав экранов сохранены.

## Проверка

Изменения frontend и backend делали два исполнителя. Затем отдельный проверяющий изучил общий diff и тесты. Он обнаружил проблему с медленными свечами; после исправления повторно проверил её и запросы сделок. Финальный запуск тестов и проверку в браузере выполнил основной агент.

- **45 Python regression tests — пройдены.** Проверены сохранность файлов базы при ошибках, реальное повреждение SQLite, миграция, конкурентная вставка новостей, валидация API, гонки запусков и порядок завершения служб.
- **15 JavaScript regression tests — пройдены.** Управляемые задержки воспроизводят переупорядочивание ответов, повторные запросы, ошибки отправки и очистки чата. Используется код из поставляемого HTML и минимальные DOM-заглушки.
- Встроенные самотесты `backend.store_v5`, `backend.api_council`, `backend.api_mission`, `backend.api_v5` — пройдены. В самотесте хранилища также закрыто соединение, мешавшее удалению временного файла на Windows.
- Все Python-модули компилируются, весь встроенный JavaScript синтаксически разбирается, `git diff --check` проходит.
- В браузере проверены шапка на ширинах 320, 360, 390, 440, 768 и 1440 px, поиск с клавиатуры, демо-миссия, график, смена интервалов, светлая и тёмная темы, сообщение и ответ демо-чата, экран журнала. Ошибок JavaScript в консоли при этих сценариях не было.

Тестовое окружение: Windows, Python 3.12.14, FastAPI 0.141.1, Starlette 1.7.0, pytest 9.1.1. Есть предупреждения об устаревающих `on_event` и использовании httpx в TestClient; это не падения тестов.

Проверки брокера и ИИ выполнялись с подменёнными сервисами (`PYTHIA_MOCK_AI=1`, `PYTHIA_MOCK_TINKOFF=1`, `PYTHIA_DRY=1`), Telegram отключён. Реальные заявки, платные AI-вызовы и сообщения Telegram не отправлялись. Эти проверки не подтверждают исполнение ордеров у реального брокера или качество торговой стратегии. Тест жизненного цикла покрывает службы старта сервера; отдельные задачи миссии, чата и пилота этим изменением не объединены в общий реестр.

## Как запустить и перепроверить

Приложение запускается прежними `start.bat` или `start.sh`. Для знакомства с исправлениями в меню запуска можно выбрать режим 3 — демо.

Дополнительные тестовые зависимости вынесены в `requirements-dev.txt`; для работы самого терминала они не нужны. Из каталога проекта на Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest tests -q
node --test tests/test_frontend.cjs
```

Для последней команды нужен установленный Node.js с поддержкой `node:test`. Сам терминал Node.js не требует.

При обновлении существующей установки сначала остановите сервер и сохраните копию каталога `data`. В поставляемом архиве `data` отсутствует: в нём нет тестовых миссий, настроек, ключей или личной базы. Исходный архив не изменялся.

## Что имеет смысл улучшить следующим отдельным этапом

1. **Доступ к API из локальной сети.** Скрипты запуска слушают `0.0.0.0`, CORS допускает любые origin, а единой проверки доступа к управляющим методам нет. Для использования с телефона стоит добавить явное сопряжение/авторизацию и ограничение origin, сохранив удобный локальный запуск. В этой сборке сетевой контракт не менялся.
2. **Разделение большого интерфейса на модули.** `frontend/index.html` занимает около 550 КБ и содержит стили, сеть, график, состояние миссии и чат. Поэтапное выделение CSS и JS по функциям упростит дальнейшие изменения и изоляцию ошибок. Начать можно с проверенных здесь поиска, графика и чата.
3. **Общий жизненный цикл фоновых задач.** Регистрация и завершение всех задач, включая совет, миссию и чат, помогут сделать перезапуск предсказуемее. Переход FastAPI на lifespan логично провести вместе с этой работой.
4. **Воспроизводимые зависимости.** Текущие диапазоны версий широкие. Проверенный lock/constraints-файл и автоматический запуск существующих самотестов плюс новых регрессионных тестов снизят риск поломки после установки свежих библиотек.
5. **Нагрузка активной миссии.** Длинный экран полезно дополнительно сгруппировать вокруг текущей позиции, ближайшего действия и ошибок; подробности контекста оставлять раскрываемыми. Изменять это лучше отдельной визуальной итерацией после наблюдения за обычной рабочей сессией.
