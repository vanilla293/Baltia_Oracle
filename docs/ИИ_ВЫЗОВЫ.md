# ИИ-вызовы ПИФИИ v5 — карта, баланс FLASH/PRO, таймауты, цена (фаза 2 · W2, 23.09.2026; 24.09.2026 — ИИ без границ; 5.4.1 — трезвый пилот; 5.4.2 — свободный пилот)

**v5.4.2 «СВОБОДНЫЙ ПИЛОТ» (28.09.2026).** Воля владельца: «ИИ должен быть свободен… а он ждём, ждём, ждём — не входит и не
выходит». Новых вызовов ИИ нет; меняется, что код делает с ответами:
1. **Молчание — не решение.** Таймаут, сбой или неразобранный ответ у двери (`mission_entry`) и в мысли о прибыли
   (`mission_profit`) — запись «НЕТ_ОТВЕТА» / «НЕ_РАЗОБРАН» (silent, источник — код), позиция и план не трогаются,
   повтор через `PYTHIA_SILENT_RETRY_SEC` (120 с). В промпты и панель они идут как «ответа не было», а не как «ЖДАТЬ» /
   «ДЕРЖАТЬ». У перепроверки неразобранный choice → повтор через `REVIEW_RETRY_SEC` без записи «ЖДЁМ».
   Трос и тейк молчат по-прежнему в безопасную сторону (СЛИТЬ / ЗАФИКСИРОВАТЬ) — это защита позиции, не вход.
2. **Разбор слова решения** — один `ai_v5.decision_of` по словарям узлов (`review_table`, `door_table`, `profit_table`,
   `guard_table`, `take_table`, `exec_table`): целые слова, Ё=Е, латиница, ключ decision|choice|do|action; «НЕ …» и
   «… или …» → переспрос. Сторона нужна: «BUY» у двери — «войти» только для плана лонга; «ВОЙТИ» у перепроверки без
   стороны не угадывается.
3. **Сроки у денег:** проверка входа и мысль о прибыли — `PYTHIA_ENTRY_TIMEOUT_SEC` / `PYTHIA_PROFIT_TIMEOUT_SEC`
   (1200 с, было 600 константой) на КАЖДУЮ попытку (`money_json(attempt_timeout=…)`: повтор после пустого/кривого
   ответа получает свой срок, таймаут попытки — без повтора); сбор данных для них ограничен отдельно (~120 с).
   Трос/тейк — 600 с, триаж — 300 с, как в 5.4.1.
4. **Меньше вызовов у двери:** свежий вход, решённый PRO по живому рынку, второй раз не спрашивается
   (`PYTHIA_ENTRY_FRESH_SEC`, `PYTHIA_ENTRY_DRIFT_PCT`); у двери — приказ совета и устаревшие планы. Больше вызовов
   перепроверки при WAIT: базовый ритм прежний — раз в `PYTHIA_WAIT_REVIEW_SEC` (1800 с = `PYTHIA_REVIEW_SEC`), плюс
   внеплановые по уровням WAIT, проколам «вне рынка» и поводам пилота без плана.

**v5.4.1 «ТРЕЗВЫЙ ПИЛОТ» (24.09.2026, W1).** Воля владельца: «FLASH принимает решения, когда PRO должен, и что долго —
мне нравится, пускай»; «входит не глядя»; «в плюсе не думает выйти — ждёт тейка, а стопы выбивают». Поэтому:
1. **Узлы у денег — PRO.** Трос (`mission_guard`), тейк (`mission_take`), триаж событий (`event_triage`), новая проверка
   входа у двери (`mission_entry`) и новая мысль о прибыли (`mission_profit`) идут через `ai_v5.money_json(system, user,
   route=…)`: модель по `PYTHIA_MONEY_MODEL` — `pro` (умолчание) или `flash` (как в 5.3); всегда с размышлением, своя
   очередь `SEM_MONEY` (только при `PYTHIA_MONEY_MODEL=flash`; PRO семафор не берёт), ровно один повтор той же моделью, без починки чужой моделью. Таймауты: GUARD 600 с, TAKE 600 с,
   ENTRY 600 с, PROFIT 600 с, TRIAGE 300 с. Молчание → безопасное правило (СЛИТЬ / ЗАФИКСИРОВАТЬ / PRO как раньше /
   входа нет / ДЕРЖАТЬ). Пока PRO думает, позицию страхует виртуальный трос в программе (`PYTHIA_EXCHANGE_STOP=0`:
   стоп-заявок на бирже нет, за тросом тик закрывает по рынку без вопросов).
2. **Голос 4.5.4.** У всех думающих и денежных узлов (кресла совета и итог, кресла миссии и шифровальщик, перепроверка,
   трос, тейк, триаж, проверка входа, мысль о прибыли, чат) в system стоит `prompts_mission.VOICE` = `PERSONA` +
   `DOCTRINE` (8 строк: кухня рынка, конкретика, сценарии, холодный расчёт, асимметрия; 5.4.2 — п.7 «свобода
   решения: все ходы равноправны, у каждого своя цена»); system ≤ 20 строк; приказ допускает `WAIT` (`wait_for` —
   чего ждать); подталкиваний нет ни к входу («главное войти, а не оттягивать» / «флета нет»), ни к ожиданию
   («не трусость», «только с перевесом», «сомнение — ждать», «вслепую» — 5.4.2, `BANNED` ловит обе стороны). Механика (разметка, потоки, разведка, рамка, толмач, память) —
   без доктрины. Роли узлов у денег в промптах не привязаны к FLASH («дежурный миссии у троса/тейка/у двери»).
3. **Пределы входов назад:** блок 60 000 симв., промпт 300 000, жёсткий потолок 450 000 (как в 5.1–5.3.2): промпты
   ×3 из 5.3.3 давали 400–600 тыс. симв., в которых модель тонула в слоях. Ножниц по-прежнему нет — выше пределов
   сжимает FLASH без потери нитей.
Мок (`PYTHIA_MOCK_AI=1`, в бой не течёт): `mission_entry` → всегда ВОЙТИ (демо входит как раньше), `mission_profit` →
всегда ДЕРЖАТЬ (триггер и цель не двигает).

**Воля владельца (24.09.2026): ИИ без границ — как это выглядит на самом деле (расследование `docs/DEEPSEEK_2026-09-24.md`).**
Режима «auto» у DeepSeek нет: `reasoning_effort` ∈ none/low/high/max, умолчание сервера high. Мы ничего не навязываем —
`reasoning_effort` не шлём, т.е. работает умолчание API (high), ровно как в первой ПИФИИ 4.5.4. Потолок ответа шлём ЯВНО
= максимум модели 393 216 токенов (`AI_MAX_TOKENS`): без параметра сервер сам режет 64K на ответ вместе с размышлением,
и 32 000 токенов ответа при глубоком размышлении не влезают. Размышление FLASH не глушится ни в одном узле решений;
`thinking=False` только там, где ИИ не судит о рынке: починка JSON и `health`. Узлы у денег (`mission_guard`, `mission_take`,
`event_triage`, `mission_entry`, `mission_profit`, `mission_exec`, `mission_review`, `summary`): пустой или кривой ответ → один
повтор той же моделью с тем же размышлением, снова плохо → «молчание» → ответ по правилу; без размышления не переспрашиваем
и чужим FLASH не «чиним». Узлы у денег на FLASH идут своей очередью (`SEM_MONEY`), а не в общей с разметкой новостей; на PRO (умолчание 5.4.1) очереди нет. Клиент:
read 3600 с, стримы — сторож простоя 600 с между чанками, таймаут повторяется один раз; `finish_reason=length` и
оборванный поток пишутся в панель проблем, обрыв помечается в тексте. Пределы входов (5.4.1): блок 60 000 симв.,
промпт 300 000 (жёсткий 450 000).
Правило JSON-режима DeepSeek: в промпте JSON-стадии должно быть слово «json» (все наши содержат) — иначе при явном
потолке модель может лить пробелы до лимита за деньги.

Каждый вызов — новый чат `system + user` через `backend/ai_v5.py` (`flash_json/flash_text/pro_json/pro_text/
pro_stream`) над `backend/ai.py` (`ask/stream`, клиент DeepSeek: read 3600 с, стримы — сторож простоя 600 с между
чанками, `_TRIES`=3 на 429/5xx/сеть/пустой ответ, таймаут — один повтор; JSON-стадии — `_json_with_repair`: у механики
кривой JSON чинится одним дешёвым FLASH `<route>_repair`, «ушла в размышления» — повтор `<route>_nothink`; у денег —
один повтор `<route>_retry` с тем же размышлением, иначе «молчание»). Учёт расхода — `ai_v5.usage()`:
итог + `by_route` {route: {calls, prompt, completion, model}} + `by_model` {FLASH|PRO}; отдаётся панели в
`GET /api/v5/state` → `tokens.by_route` / `tokens.by_model` (для панели фазы 3).

Обозначения: **think** — размышление модели включено; «таймаут» — явный `asyncio.wait_for` вокруг вызова
(без него — только клиентский read 3600 с и один повтор по таймауту); «час спокойно» — обычный день с одной миссией
и живым дозором; «час буря» — шквал новостей, резкие ходы, позиция у троса/тейка. Токены — типичный
объём промпта из `status()["sizes"]` (символы ≈ токены × 3). Цена в рублях здесь не приводится: тариф
DeepSeek меняется — считай по `tokens.by_route` панели; порядок: FLASH — копейки за вызов, PRO с think —
в десятки раз дороже за тот же промпт и в разы дольше.

| `health` | `ai.health` (`/api/v5/health`) | по запросу панели | FLASH, `max_tokens` 20 | клиент | статус «ключ не отвечает» | 0–1 | 0–1 | 1 строка |
| `aip_review` | `ai_pilot._review` (пилот 4.x) | только `PYTHIA_LEGACY_PILOT=1` | по `ai.ask_json` (PRO) | 300 с | «держу как есть» | 0 | 0 | — |

Совет по рынку (этап 1) без миссии за спокойный день: ~5–10 FLASH-вызовов разметки, 1–3 группировки,
3 PRO-кресла + итог. Миссия за спокойный час (5.4.1): 2 PRO-перепроверки, 0–2 проверки входа у двери (PRO),
0–1 мысль о прибыли (PRO), 0–1 триаж (PRO), 0–1 тейк/трос (PRO), 2–6 FLASH толмача. Буря за час: до 2 советов
миссии (6 PRO-кресел + 2 шифровальщика), до 4 PRO-перепроверок, 2–6 проверок входа, 1–3 мысли о прибыли,
2–4 триажа, 1–3 ответа у троса, 1–2 у тейка, 10–20 объяснений — PRO ограничен пейсингом
(`PYTHIA_EVENT_COOL_SEC`, `EVENT_MIN_GAP_SEC`, `PYTHIA_COUNCIL_GAP_SEC`, `PYTHIA_ENTRY_CHECK_COOL_SEC`,
`PYTHIA_PROFIT_THINK_COOL_SEC`), FLASH — считанные секунды и копейки. Узлы у денег на PRO — в разы дороже и
дольше, чем на FLASH в 5.3: воля владельца («пусть думает долго, но решает тот, кто должен»); вернуть
дешёвый путь — `PYTHIA_MONEY_MODEL=flash`.

## Где FLASH, где PRO — и почему (5.4.1)

- **PRO (думает, дорого, минуты)** — везде, где решение о деньгах принимается по картине: три кресла и итог
  совета по рынку, три кресла + шифровальщик совета миссии, дежурная перепроверка (раз в 30 мин и по событию),
  чат владельца по умолчанию — **и с 5.4.1 все узлы у денег**: трос (`mission_guard`), тейк (`mission_take`),
  триаж событий (`event_triage`), проверка входа у двери (`mission_entry`), мысль о прибыли (`mission_profit`) —
  через `ai_v5.money_json`, модель по `PYTHIA_MONEY_MODEL` (умолчание `pro`). Воля владельца 24.09.2026: «теперь
  FLASH принимает решения, когда PRO должен, и что долго — мне нравится, пускай». Шифровальщик оставлен на PRO
  сознательно: приказ с числами входа, тейка и стопа — самое дорогое место, ошибка дороже вызова. Единственный
  PRO без явного таймаута — стримовые кресла: там действует клиентский read 3600 с, сторож простоя стрима 600 с,
  и владелец видит стрим.
- **Долго, но не вечно.** Таймауты узлов у денег: GUARD 600 с, TAKE 600 с, ENTRY и PROFIT — 5.4.2:
  `PYTHIA_ENTRY_TIMEOUT_SEC` / `PYTHIA_PROFIT_TIMEOUT_SEC` (1200 с на попытку; в 5.4.1 — 600 с), TRIAGE 300 с
  (были 120/120/90 на FLASH). Молчание модели у троса и тейка решается в безопасную сторону (СЛИТЬ /
  ЗАФИКСИРОВАТЬ), после триажа — PRO-перепроверка как раньше; у двери и в мысли о прибыли (5.4.2) молчание —
  не решение: «НЕТ_ОТВЕТА», позиция и план как есть, повтор через `PYTHIA_SILENT_RETRY_SEC`. Пока PRO думает у троса, позицию страхует
  виртуальный трос в программе (`PYTHIA_EXCHANGE_STOP=0`, умолчание: за ним тик закрывает по рынку без вопросов;
  `=1` — трос на бирже, как в 5.4.0).
- **FLASH (быстро, дёшево, секунды)** — механика и всё, что должно случиться за секунды: отбор и разметка
  новостей, группировка, раскладка, разведка, рамка, влияние дозора, сжатие, толмач и память, `health`.
  У денег FLASH только по `PYTHIA_MONEY_MODEL=flash` (как в 5.3): тогда те же узлы идут на FLASH с размышлением,
  своей очередью и теми же безопасными ответами по умолчанию.
- **Триаж больше не «сверхбыстрый»**: на PRO ответ — секунды–минуты (таймаут 300 с), но он по-прежнему стоит
  перед дорогой полной перепроверкой и в спокойный день снимает половину внеплановых перепроверок (ПЛАНОВО/САМ),
  в бурю — не даёт каждому ходу будить перепроверку; промпт короткий (ситуация, ход цены, живой рынок за 8 с,
  план, прошлая перепроверка, память, новости из хранилища — без сканера и разведки).
- **Проверка входа у двери** — PRO-вызов на заявку входа по приказу совета и по устаревшему плану (5.4.2: свежее
  решение PRO — перепроверка, уровень от двери, перезаход, добор — ≤ `PYTHIA_ENTRY_FRESH_SEC` и без дрейфа хуже
  `PYTHIA_ENTRY_DRIFT_PCT` — бьётся без двери): решение принято раньше, а рынок с тех пор жил — сверить его с живым
  рынком, ВОЙТИ / ЖДАТЬ / ОТМЕНИТЬ равноправны; ЖДАТЬ — новый уровень (entry, entry_kind) или срок (wait_minutes),
  ОТМЕНИТЬ — план снят (council=true → полный совет). Цена — 0–2 вызова в спокойный час; при ЖДАТЬ без уровня повтор не
  раньше `PYTHIA_ENTRY_CHECK_COOL_SEC` (300 с), при молчании — «НЕТ_ОТВЕТА», повтор через `PYTHIA_SILENT_RETRY_SEC` (120 с).
- **Мысль о прибыли** — PRO думает в плюсе, не дожидаясь тейка (владелец: «когда норм плюс, можно выйти… видно,
  что это рывок и можно перезайти»): не чаще `PYTHIA_PROFIT_THINK_COOL_SEC` (900 с), повод — доля хода до тейка
  или рывок; ДЕРЖАТЬ может подтянуть триггер (lock_price) и цель (take), ВЫЙТИ_И_ПЕРЕЗАЙТИ — план той же стороны
  (5.4.2: по этому решению, пока оно свежее, позже — через проверку входа), СОВЕТ — полный совет без очереди (handoff
  kind `profit`); молчание — «НЕТ_ОТВЕТА», позиция как есть, повтор через `PYTHIA_SILENT_RETRY_SEC`.
- **Толмач/память** — FLASH по умолчанию (`PYTHIA_EXPLAIN_MODEL=pro` — дороже, но можно).
- **Прокол сканера (W3)** — нового маршрута нет: `MissionPilot._puncture_watch` (без ИИ, по кэшированному
  `maya_scan.status()`, раз в 5 с) собирает блок ПРОКОЛ СКАНЕРА и кладёт его первым в ситуацию существующих
  вызовов: в позиции — `event_triage` и дальше по вердикту, вне рынка — `mission_review`
  (PRO). Цена — не чаще одной перепроверки в `PYTHIA_PUNCTURE_COOL_SEC` (10 мин) и один прокол (сторона +
  полоса + роль) — одна перепроверка; в спокойный час 0–1 лишняя перепроверка, в бурю пейсинг тот же.

## Дыры, найденные при обходе, и что сделано (W2)

1. `watch.impact` (FLASH с think) звался без явного таймаута: зависший ответ держал тик дозора до
   клиентского таймаута (600 с × 3 = до 30 мин), а следующие проходы дозора ждали. Починено минимально:
   `asyncio.wait_for(…, IMPACT_TIMEOUT=240)` (тогда; сейчас 480) — тик падает честно стадией `error`, следующий через
   `PYTHIA_WATCH_SEC`.
2. Учёта по маршрутам не было (только общий счётчик `ai.tokens()`): `ai._add_usage(usage, route, model)`
   → `ai.tokens_by_route()` → `ai_v5.usage()["by_route"/"by_model"]` → `/api/v5/state.tokens`.
3. Стадии `newsflow` (`triage`, `characterize`, `group`, `distribute`) и кресла совета — без явного
   `wait_for`, но с клиентским таймаутом и повторами; сбой не роняет этап (пачка/новость помечается,
   остальное идёт). Оставлено как есть: это интерактивные прогоны, владелец видит степпер.
4. «PRO там, где хватит FLASH»: кандидатов два — `summary` (итог совета в JSON из вердикта) и
   `mission_exec` (шифровальщик). Не менялось: оба дают числа, по которым торгуют; экономия — один
   PRO-вызов за совет. «FLASH там, где нужен PRO» — не найдено: все решения о входе/закрытии по картине —
   PRO, FLASH у денег только с безопасным ответом по умолчанию.
5. Сделано (фаза 3 · W1): PRO промолчал на перепроверке (таймаут — тогда 300 с, сейчас 1200 / сеть / не JSON) →
   `MissionPilot._review_silent`: ранняя повторная попытка через `REVIEW_RETRY_SEC` (5 мин), как при
   «шифровщик не дал exec»; повод не теряется; ошибка — в `ai_v5.last_error()` для панели проблем.
6. 5.4.1 (владелец: «входит не глядя», «стопы выбивают, а должна сидеть и думать»): между приказом совета и заявкой
   не было ни одного взгляда на живой рынок, а в плюсе ИИ ждал только тейка. Закрыто: проверка входа у двери
   (`mission_entry`) перед каждой заявкой и мысль о прибыли (`mission_profit`) в плюсе — оба PRO, оба с безопасным
   ответом по умолчанию (входа нет / ДЕРЖАТЬ) при молчании. Пункт 4 выше («FLASH у денег только с безопасным
   ответом») — история 5.3: с 5.4.1 у денег PRO.

## Стенд промптов (5.4.3) — не боевой вызов

`backend/prompt_bench.py` зовёт те же маршруты, что бой (`mission_review` — `pro_json`, 1200 с; `mission_entry` /
`mission_profit` — `money_json`; вердикт — `pro_text` с маршрутом `mission_verdict` вместо боевого `pro_stream`), но
только по команде владельца: `python3 -m backend.prompt_bench --run [--runs N]` — 14 выдуманных ситуаций × N прогонов
(≈ 14 вызовов PRO на прогон, каждый 20–100 тыс. симв. промпта). Без ключа и без `PYTHIA_MOCK_AI=1` — выход с кодом 2;
без аргументов — self-тест на фейках (ИИ не зовётся); `--dump DIR` — только промпты в файлы.
