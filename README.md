# ПИФИЯ v5 «СОВЕТ»

Локальный торговый терминал: новости → совет ИИ → взгляд человека → миссия
по инструменту с ИИ-пилотом у брокера Tinkoff. Бэкенд — FastAPI, фронт — один
HTML-файл, ИИ — DeepSeek (FLASH для механики, PRO для совета и — с 5.4.1 — для узлов у денег). Всё по-русски.

## Запуск

```
Windows:      start.bat
Linux/macOS:  ./start.sh
```
Скрипт сначала проверяет Python (3.10+), создаёт `.venv` и ставит зависимости
(видно, с проверкой импорта и до трёх повторов, лог в `data/install.log`), потом
спрашивает режим (1 боевой, 2 сухой — по умолчанию, 3 демо), докачивает
эфемериды и поднимает `backend.server:app` на http://localhost:8799 (порт —
переменная `PORT`). Любой сбой останавливает окно с понятным текстом, а не
крашится. Папку проекта держи вне OneDrive / Яндекс Диска / Google Диска:
облако блокирует файлы во время установки, и `.venv` ломается (лечится
переносом папки, например в `C:\pythia`, и удалением `.venv`).
Ручной запуск: `python3 -m uvicorn backend.server:app --host 0.0.0.0 --port 8799`.

## Ключи

В панели — кнопка **Ключи**: ключ(и) DeepSeek (можно несколько — пул
аккаунтов), токен Tinkoff (с правом торговли, если нужен пилот) и токен + chat_id Telegram-бота
(раздел «Telegram-бот» ниже). Хранятся в `data/config_user.json`. Без токена Tinkoff совет и приказ считаются, пилот не
стартует. Кнопка «Проверить DeepSeek» дёргает `/api/v5/health`; «Проверить бота» — `POST /api/v5/telegram/test`
(getMe + «ПИФИЯ на связи» в чат, ответ человеческим текстом: «токена бота нет», «чат не привязан — напиши боту /start»,
«бот отвечает, сообщение ушло»); «Отвязать Telegram» — `DELETE /api/v5/keys?what=telegram` (DeepSeek и Tinkoff остаются).
Под полями Telegram — статус масками: «задан: 12…xx · чат •••» или «чат не привязан — напиши боту /start, впиши chat_id».
Панель проверяет вид до отправки: токен `цифры:латиница` (как выдал BotFather), chat_id — целое число (у групп с минусом).

## 5.4.2 — свободный пилот

Владелец 28.09.2026, тестируя DeepSeek на бирже для отчёта: «ИИ должен быть полностью свободен — без морали, использует
мои данные, как сам решит, и сам принимает решения; а он ждём, ждём, ждём — не входит и не выходит». Причины нашлись и в
промптах, и в коде (аудит — 7 веток параллельно, каждая находка проверена независимыми проверяющими):

1. **Промпты без перекоса ни в одну сторону.** В 5.4.1 пункт 7 доктрины («нет перевеса — вне рынка, это решение, а не
   трусость; вход без перевеса хуже пропущенного») стоял во всех 17 думающих узлах, а вердикт («вход — только с
   перевесом»), шифровальщик («в рынок не лезем»), перепроверка («ЖДЁМ — решение, не трусость») и проверка у двери
   («не входить вслепую… сомнение — ЖДАТЬ») добавляли своё. Теперь п.7 — **свобода решения**: войти, добрать,
   держать, выйти, перевернуть или стоять вне рынка — равноправные ходы, у каждого своя цена (лишний вход стоит
   стопа, пропущенный ход — непойманной прибыли). Критик ищет и слабый вход, и упущенный ход; шифровальщик переводит
   вердикт как есть; приказ WAIT для перепроверки — ориентир, а не условие; ЖДЁМ не стоит первым в списке ответов.
   `prompts_mission.BANNED` ловит подталкивания в обе стороны (и «главное войти», и «не трусость»).
2. **Молчание ИИ — не его решение.** Таймаут, сбой или непонятный ответ у двери и в мысли о прибыли раньше
   записывались как «PRO: ЖДАТЬ» / «ДЕРЖАТЬ» и снова шли ИИ в промпт как его прошлый выбор. Теперь это «НЕТ_ОТВЕТА» /
   «НЕ_РАЗОБРАН» (в панели серым «решения не было»), вопрос повторяется через `PYTHIA_SILENT_RETRY_SEC` (120 с), а не
   через 5–15 мин. Входом молчание тоже не становится.
3. **Слово решения понимается.** Один разбор `ai_v5.decision_of` для всех узлов: «BUY», «ЛОНГ», «CLOSE»,
   «ЗАФИКСИРОВАТЬ», «Ждём!» понимаются правильно (раньше «BUY»/«CLOSE» у перепроверки молча становились ЖДЁМ, а
   «НЕ ВХОДИТЬ» у двери — входом); «НЕ …» и «… или …» → переспрос.
4. **Без второго вето.** Вход, который PRO решил сам по живому рынку (перепроверка, уровень, названный у двери,
   перезаход из мысли о прибыли), бьётся без второго вопроса у двери, если решению не больше
   `PYTHIA_ENTRY_FRESH_SEC` (20 мин) и цена не ушла дальше `PYTHIA_ENTRY_DRIFT_PCT` (1 %). Приказ совета (он старше)
   проверяется у двери, как в 5.4.1. Цена убежала, пока ИИ думал, — новый вопрос с живой ценой, а не молчаливая засада
   по старой цене.
5. **WAIT не спит вслепую.** Базовый ритм тот же — дежурный PRO смотрит рынок раз в 30 мин (`PYTHIA_WAIT_REVIEW_SEC`,
   по умолчанию = `PYTHIA_REVIEW_SEC`), но раньше его будят триггеры: уровни приказа WAIT, прокол сканера «вне рынка»,
   резкий ход, серьёзная новость; «приказ протух», «идея мертва до входа»,
   ОТМЕНИТЬ у двери — перепроверка через минуты, а не на плановой.
6. **Прочее из аудита.** Стоп-кран дня (killswitch) считает убыток по сделке, а не по каждой частичке закрытия (одна
   сделка тремя кусками раньше давала «3 убытка подряд» и запирала день); у каждой попытки PRO у денег свой срок;
   классический стоп пробоя (между ценой и уровнем пробоя) больше не отклоняется; первый совет без приказа не
   оставляет миссию мёртвой — пилот поднимается без плана и спрашивает PRO; переворот при молодой позиции — хотя бы
   выход; совет ночью и в выходной не пустеет (список входов на ближайшую торговую сессию); тесты исполнения больше
   не зависят от времени суток.

**Как вернуть поведение 5.4.1:** `PYTHIA_ENTRY_FRESH_SEC=0` (каждый вход снова через дверь),
`PYTHIA_ENTRY_TIMEOUT_SEC=600`, `PYTHIA_PROFIT_TIMEOUT_SEC=600`. Промпты 5.4.1 — только из истории git.

**Для отчёта о DeepSeek.** Решения ИИ и правила кода теперь разделены: «НЕТ_ОТВЕТА» / «НЕ_РАЗОБРАН» / «ВНЕ_РЕЖИМА» —
не выбор модели. Время с `РЫНОК_ЗАКРЫТ` (фаза `closed`) — тоже не её выбор: без токена Tinkoff часы идут по статическому
расписанию, где выходные закрыты. Для честного теста — режим игры `auto` или `mixed` (в `long`/`short` вход в
запрещённую сторону не исполняется).

## 5.4.1 — трезвый пилот

Владелец 24.09.2026, посмотрев 5.4.0 в деле: «раньше он был более трезвый и свободный… нынешняя версия, когда
ставит вход, входит не глядя… FLASH принимает решения, когда PRO должен… на бирже выставляет стопы, когда они должны
быть только в программе… когда норм плюс, можно выйти — не думает выйти, хочет лишь тейка, стопы выбивают, хотя
должна иишка сидеть и думать, надо ли выходить, а может совет открыть». Пять правок:

1. **Стопы только в программе.** Стоп-заявок на бирже нет: трос виртуальный, за ним тик закрывает по рынку без
   вопросов. Переключатель **«Трос на бирже»** в «Ключах» (`PYTHIA_EXCHANGE_STOP`, по умолчанию выключен).
   **Предупреждение:** при падении программы, зависании или обрыве связи позиция остаётся без защиты — это
   осознанный выбор владельца; панель напоминает бейджем «трос в программе» в «Сейчас», подписью «трос (в программе)»
   в плитке пилота и на графике, подсказкой в «Ключах».
2. **Узлы у денег — PRO.** Трос, тейк, триаж событий, проверка входа и мысль о прибыли решает PRO (думает долго —
   минуты; трос за это время страхует; молчание у троса и тейка → безопасное правило, у двери и в мысли о прибыли —
   с 5.4.2 «решения не было» и скорый повтор). Переключатель **«Узлы у денег: PRO / FLASH»**
   в «Ключах» (`PYTHIA_MONEY_MODEL`, `flash` — как в 5.3).
3. **Проверка входа у двери.** Перед каждой заявкой входа по плану (сейчас / откат / прорыв; добор по решению PRO и
   переворот — тоже) PRO смотрит живой рынок: ВОЙТИ / ЖДАТЬ (новый уровень или срок, можно поправить стоп и тейк) /
   ОТМЕНИТЬ (план снят; может позвать полный совет). Молчание — входа нет, повтор через `PYTHIA_ENTRY_CHECK_COOL_SEC`
   (5.4.2: молчание — «решения не было», повтор через `PYTHIA_SILENT_RETRY_SEC`; свежее решение PRO дверь не проверяет).
4. **Мысль о прибыли.** В плюсе PRO думает, не дожидаясь тейка (пройдено ≥ `PYTHIA_PROFIT_THINK_PCT` % хода до
   тейка, без тейка — плюс ≥ `PYTHIA_PROFIT_THINK_MIN_PCT` %, или рывок в нашу сторону): ДЕРЖАТЬ (подтянуть триггер /
   цель) / ВЫЙТИ / ВЫЙТИ_И_ПЕРЕЗАЙТИ (план той же стороны; с 5.4.2 вход по этому решению, пока оно свежее, позже —
   через проверку входа) / СОВЕТ. Не чаще
   `PYTHIA_PROFIT_THINK_COOL_SEC`.
5. **Голос 4.5.4 и пределы входов.** Компактная доктрина во всех думающих узлах (кухня рынка, конкретика с числами и
   таймингом, сценарии с триггерами и отменой; с 5.4.2 — свобода решения: все ходы равноправны), приказ совета `WAIT`
   («ВНЕ РЫНКА — ждём: …» в карточке приказа, входа и уровней нет, дежурный PRO вернётся на перепроверке), без
   подталкиваний ни к входу, ни к ожиданию;
   пределы входов 60 000 / 300 000 / 450 000 символов.

**Как вернуть прежнее поведение:** «Ключи» → включить «Трос на бирже» и выбрать «FLASH» (действует сразу, пишется в
`data/config_user.json`); проверку входа и мысль о прибыли выключают переменные `PYTHIA_ENTRY_CHECK=0` и
`PYTHIA_PROFIT_THINK=0`. Панель: бейджи «PRO проверяет вход…» / «PRO думает о прибыли…», строки последней проверки
входа и последней мысли о прибыли в карточке пилота, записи «PRO · вход: …» / «PRO · прибыль: …» в хронике, узлы
«проверка входа» и «мысль о прибыли» у толмача.

## Четыре шага

1. **Новости → Совет.** RSS за N дней (по умолчанию 3) → FLASH отбирает
   биржевое → размечает каждую новость (тон, честность, раздутость, важность,
   эффект, активы…) → группирует в потоки → PRO: анализ → критика → вердикт →
   итог-JSON (режим, входы с уровнями и уверенностью, чего избегать, ключевые
   часы) → FLASH раскладывает выбор по тикерам и прикрепляет новости. Тексты
   трёх кресел стримятся в панель.
2. **Мой взгляд.** Текст человека → FLASH сжимает и сортирует по активам (ничего
   не теряя) → PRO пересматривает итог с учётом взгляда → по каждому тезису:
   согласен / частично / нет → рамка «к чему пришли и почему».
3. **Миссия.** Инструмент + способ игры (лонг / шорт / смешанно / решает ИИ) →
   досье биржи + итог совета + новости + астро + Курамото/бифуркации → PRO совет
   по инструменту → exec-приказ (BUY/SELL/WAIT, тейк/стоп, вход сейчас / на откате
   к уровню / на пробитии уровня) → пилот: проверка входа у двери (PRO: войти /
   ждать / отменить), вход на максимум с плечом, трос в программе; в плюсе PRO
   думает о выходе, не дожидаясь тейка;
   дежурный PRO раз в 30 мин думает и решает (ждать / войти / закрыть / звать
   совет), внепланово — по резкому ходу цены или серьёзной новости; полный
   совет зовёт сам PRO. Кнопки СТОП / ПРОДОЛЖИТЬ / ПЕРЕСМОТР / ПАНИКА, график
   с уровнями и сделками.
4. **Журнал.** Сделки (чистый результат по операциям брокера, победы/потери), кривая, итоги по дням,
   история советов.

## Журнал: чистый результат (фаза 4 · W1)

Пилот пишет сделку в момент закрытия по цене тика — это оценка. Слой `backend/ledger.py` читает
исполненные операции счёта (Tinkoff `GetOperationsByCursor`, только чтение) и сверяет их с журналом:
настоящие цены входа и выхода (VWAP исполнений), комиссии входа и выхода, брутто по деньгам операций и
**нетто = брутто − комиссии**. Сделки, которых в журнале нет (сервер лежал, владелец закрыл руками), собираются
из операций и добавляются с причиной «по операциям брокера». Сверка идёт сама через ~20 с после закрытия и фоном
(раз в 5 мин при живой миссии, раз в час иначе); кнопка «Сверить с брокером» на экране «Журнал» и
`POST /api/v5/trades/sync` — вручную. Без операций (сухой прогон, нет токена) сделки остаются оценочными:
комиссия считается как оборот × `PYTHIA_FEE_PCT` и честно помечается «оценка». Итоги дня —
`GET /api/v5/trades/day?date=YYYY-MM-DD` (по МСК): сделки, нетто/брутто/комиссии, плата за маржу, лучшая/худшая,
сессионный P/L пилота, деньги на счёте — эта же форма уходит в Telegram (`/day` и итоги дня).

Экран «Журнал» (фаза 4 · W3): шесть плиток — сделок (сколько сверено), **чистыми** крупно с бейджем «брокер»/«оценка»
(средняя, лучшая, худшая), брутто (по ценам исполнения брокера или по тику), комиссии (с пометкой «оценка», пока брокер
не подтвердил; доля от брутто), win rate и профит-фактор — всё по нетто; «сверено HH:MM» у кнопки «Сверить с брокером»
(последнее чтение операций); кривая итога по нетто; блок «По дням» (МСК: сделок, чистыми, брутто, комиссии — из `by_day`
сервера, клик по дню фильтрует сделки, повторный снимает); таблица сделок: вход и выход по ценам брокера (тик подписью),
брутто, комиссия, чистыми, источник (брокер / мок-брокер / частично / оценка), причина. Пустой журнал честно говорит,
откуда берутся сделки: закрытия пилота и операции брокера. Карточка «Сделки миссии» — чистыми, комиссии, «сверено HH:MM».
Событие сверки (`scope ledger`, `stage reconcile`) обновляет открытый журнал и показывает тост «Сверено с брокером: … чистыми …».

## Telegram-бот: как привязать (фаза 4 · W2)

Бот присылает уведомления (приказ совета; вход, добор и закрытие сделки с числами; решения FLASH у троса и тейка;
объяснения толмача; перепроверки PRO; итог совета; сверка сделки с брокером «чистыми»; проблемы — не чаще раза в
10 мин на вид) и итоги дня (18:55 и 23:55 МСК, если биржа торговала; утром — «рынок открылся, позиция такая-то»).
Через бота видно всё: `/status`, `/pos`, `/trades`, `/day [ГГГГ-ММ-ДД]`, `/explain`, `/health`, `/council`, `/help`;
управление `/stop` и `/panic` — только после вопроса и ответа «да» в течение 60 с.

1. В Telegram открой **@BotFather** → `/newbot` → имя → получи токен вида `123456789:AAAA…`.
2. В панели ПИФИИ нажми **Ключи** и вставь токен в поле «Telegram-бот» (хранится в `data/config_user.json`,
   в панели видна только маска). Сервер перезапускать не нужно — бот проснётся сам.
3. Напиши своему боту `/start` — он ответит: «чат не привязан; твой chat_id: N».
4. Впиши этот chat_id в панели «Ключи» (поле «Telegram chat_id»), нажми «Сохранить» → «Проверить бота»
   (`POST /api/v5/telegram/test`) — придёт «ПИФИЯ на связи». Чужие чаты получают только свой chat_id.

Без токена бот спит (в панели проблем — ничего), с токеном без chat_id — подсказка «напиши боту /start»; 401/429/сеть —
в лог и в панель проблем (kind `telegram`), ничего не падает. Выключить: `PYTHIA_TG=0`; без итогов дня —
`PYTHIA_TG_DAILY=0`. Стереть привязку: `DELETE /api/v5/keys?what=telegram` (кнопка «Стереть ключи» стирает и её).

## Дозор

Фоном каждые `PYTHIA_WATCH_SEC` (15 мин): свежие новости → отбор → разметка →
FLASH решает, меняет ли это картину (severity 0..100). Заметки — в правой
колонке; severity ≥ `PYTHIA_WATCH_SERIOUS` (75) → активная миссия идёт на
пересмотр. Кнопка «Пересчитать совет с учётом новостей» — `update_with_news`.

## Режимы

- **Боевой** — есть токен Tinkoff и не задан `PYTHIA_DRY`: пилот выставляет
  настоящие заявки. Панель спрашивает подтверждение перед запуском миссии.
- **Сухой** — `PYTHIA_DRY=1`: ордера считаются и пишутся в
  `data/trader_audit.jsonl`, в сеть не уходят.
- **Демо** — `PYTHIA_MOCK_AI=1`: ИИ, новости, MOEX подменены фейками; ключи и
  сеть не нужны. `PYTHIA_MOCK_TINKOFF=1` добавляет фейкового брокера (депозит
  100 000 ₽, dry) — пилот входит и ведёт позицию на синтетике.

## Весь счёт, мягкий стоп, разведка, чат (v5.2)

- **Весь счёт по инструменту.** Пилот ведёт всё, что лежит на счёте по бумаге миссии: докупил или продал
  руками — это его позиция (вход = средняя брокера, P/L в журнал). ИИ не думает, сколько куплено: приказ
  BUY/SELL — код берёт столько, сколько даёт биржа с плечом (GetMaxLots), и добирает после входа, если
  биржа даёт ещё. Поле «Ограничить сумму» — только потолок; пусто — весь счёт.
- **CLOSE / ДОБРАТЬ / ПЕРЕВЕРНУТЬ.** Совет может приказать закрыть позицию и стоять вне рынка; дежурный
  PRO на перепроверке — добрать до максимума или перевернуть.
- **Мягкий стоп.** У уровня «идея мертва» позиция не бьётся стопом вслепую: FLASH за секунды получает
  максимум данных (ход цены, стакан и лента, план, новости, совет, разведка) и решает — слить или подождать
  и передать задачу Совету (полный совет без очереди). На бирже лежит аварийный трос на
  `PYTHIA_HARD_STOP_PCT` % дальше — за ним закрытие без вопросов.
- **Мягкий тейк (W2).** У цели прибыль тоже не несётся в кассу вслепую: FLASH с теми же данными, что у
  троса, решает — зафиксировать сейчас или подержать и передать задачу Совету. «Подержать» — прибыль
  запирается: триггер подтягивается к названному FLASH уровню (не ниже входа + `PYTHIA_TAKE_LOCK_PCT` %
  хода до цели), аварийный трос биржи переставляется за ним (но не ниже входа — при малой цели худший исход
  «в ноль», не убыток), тейк отодвигается на новую цель или снимается;
  Совет видит, где мы и что было, и решает с учётом свежих новостей. Подержать можно
  `PYTHIA_SOFT_TAKE_MAX_HOLDS` раз, дальше фиксация; FLASH молчит — фиксация. `PYTHIA_SOFT_TAKE=0` — тейк
  закрывает как раньше.
- **Триаж событий (W2).** Резкий ход или серьёзная новость при позиции сначала смотрит FLASH за секунды
  (`PYTHIA_EVENT_TRIAGE`): СЕЙЧАС — дежурный PRO разбужен как раньше (с пейсингом); ПЛАНОВО — повод копится
  к плановой перепроверке; САМ — подтянуть триггер в безопасную сторону или снять план добора без PRO.
  FLASH молчит — PRO как раньше. В хронике пилота у повода видно вердикт триажа.
- **Прокол сканера как повод (W3).** Сканер стакана часами видит полосы устойчивого вакуума — «проколы», куда
  цена может пройти быстро. Когда стойкость полосы ≥ `PYTHIA_PUNCTURE_MIN` (60 %) и сторона важна — вне рынка
  с планом входа (в сторону плана — возможный вход, против — предупреждение) или в позиции (против нас —
  угроза, за нас — подтверждение), — пилот собирает блок «ПРОКОЛ СКАНЕРА» (сторона, стойкость, полоса, тяга,
  серия тиков, агрессор, Хоукс, натяжение, что это значит для нас) и ставит его первым в ситуацию: в позиции
  сначала FLASH-триаж, вне рынка — сразу внеплановая перепроверка PRO. Не чаще раза в `PYTHIA_PUNCTURE_COOL_SEC`
  (10 мин), один прокол — одна перепроверка. В карточке сканера — блок «Прокол» (что видим и что делаем:
  PRO думает / повод к плановой / подтянут трос / тишина с причиной), в хронике повод «прокол», у толмача 🕳.
  `PYTHIA_PUNCTURE=0` — прокол остаётся строкой в блоке сканера.
- **Разведка данных.** Перед аналитиком FLASH смотрит, что получит PRO, и запрашивает недостающее: фьючерс
  на индекс (MX/RI у Tinkoff) сейчас и за неделю, соседей по сектору, курс, нефть — блок «ДАННЫЕ ПО ЗАПРОСУ
  РАЗВЕДКИ». Перепроверка и трос берут те же данные свежими. Индексы MOEX ISS (IMOEX, RTSI, отраслевые)
  не используются вовсе — их данные отстают; без токена Tinkoff индексных данных честно нет.
- **Связанные бумаги.** Для инструмента миссии `correlate.py` считает ρ Пирсона по дневным доходностям
  (60 дней) с соседями по сектору (банки, нефть и газ, металлы, ритейл, телеком, IT, энергетика, транспорт,
  застройщики, химия) и макро-фьючерсами (Si/CR рубль, BR нефть, GD золото, NG газ, MX/RI индексы),
  замечает опережение на день, ход за день и за 5 дней — блок «СВЯЗАННЫЕ БУМАГИ» у аналитика, критика,
  вердикта, перепроверки, троса и чата; разведка сама добавляет по ним свежие котировки. Кэш 6 ч; стадия
  «Связанные бумаги» в степпере миссии; `status()["partners"]`.
- **Чат с ИИ.** Наведи на правый край экрана (на телефоне — круглая кнопка): панель выезжает, спрашивай
  что угодно — ИИ видит миссию и пилота, позицию, совет, живой рынок, дозор, новости и сам делает разведку
  под вопрос. PRO (думает) или FLASH (быстро). Из чата приказов бирже нет — только советы и кнопки.
- **Паника без пилота.** Кнопка ПАНИКА закрывает позицию по инструменту прямо на счёте и снимает
  стоп-заявки, даже если пилот остановлен. Если проверка невозможна (не читается база миссий или файл
  состояния, биржа не отдала список стопов), первая ПАНИКА честно откажет с причиной, а повторная в течение
  двух минут (или `{"force": true}` в API) закроет по счёту напрямую, сняв заявки и стопы, что удалось. То же,
  если закрытие «ждёт подтверждения» биржи: повторное нажатие в две минуты снимает живые заявки и закрывает по
  свежему портфелю. После ПАНИКИ пилот стоит: новая миссия по тому же тикеру — сначала СТОП.
- **Ошибки биржи с текстом.** Отказы Tinkoff приходят с кодом и объяснением («30042: недостаточно
  средств…»), а не «биржа отказала».

## Рыночные часы (market_clock)

«Запустил — пришло время, биржа закрыта — программа стопорится; новости в фоне копятся».
`backend/market_clock.py` берёт «сейчас» не с часов машины, а со сдвигом к серверу биржи (заголовок
`Date` ответа Tinkoff, без токена — MOEX ISS, без сети — локальные часы с предупреждением) и спрашивает
статус торгов: Tinkoff `GetTradingStatus` (кэш 60 с) + `TradingSchedules` **по площадке бумаги** (поле
`exchange` инструмента: SBER/GAZP — `MOEX_MRNG_EVNG_E_WKND_DLR`, фьючерсы — `FORTS_FUTURES_WEEKEND`; кэш 6 ч по
площадке). Окна сделок дня — с аукциона открытия + 10 мин (в выходные 09:50 → 10:00) до конца дня биржи, внутри —
паузы по классу актива (акции: 09:50–10:00, аукцион закрытия 18:40–18:50, пауза 18:50–19:05; фьючерсы: клиринги
14:00–14:05 и 18:45–19:05); сессии утренняя (с 07:00) / основная / вечерняя / выходная. Поэтому часы говорят
«закрыт до 07:00 МСК», а не «до 10:00», когда бумага торгуется с утра, и «до 10:00 (выходной: сделки с 10:00
после аукциона 09:50)» в субботу. Открыто сейчас — только по статусу биржи; разошлись — статус главнее, в
`note` честно. Без токена — статический регламент по классу актива (акции 07:00–09:50, 10:00–18:40, 19:05–23:50;
фьючерсы 07:00–23:50 с клирингами; валюта 07:00–23:50; выходные без токена — закрыто) с честной пометкой. При закрытом
рынке пилот не входит, не добирает и не перевыставляет заявки (состояние `РЫНОК_ЗАКРЫТ`, фаза «Рынок
закрыт до …»), FLASH у троса не спрашивают (аварийный трос лежит на бирже), перепроверка и серьёзные
новости дозора копятся к открытию; петля тикает раз в `PYTHIA_CLOSED_TICK_SEC`. На открытии — сразу сверка
со счётом и (если закрыт был дольше 30 мин) перепроверка дежурного PRO с поводом «рынок открылся:
накопились новости/события» и заметками дозора за ночь; короткий клиринг просто пережидается. Совет и
приказ при закрытом рынке разрешены — ИИ видит строку `РЫНОК: рынок закрыт до 07:00 МСК (…) — вход
возможен только с открытия`. В шапке панели — пилюля «Биржа: открыта / закрыта до …», в `GET /api/v5/state`
— поле `market` {open, reason, next_open_ts, session, exchange, sessions_today, skew_s, …}.

## Толмач и память миссии (explain.py, v5.3)

«Отдельный FLASH, который каждое решение подробно описывает владельцу — непонятно, что происходит,
после совета одна и та же картинка»; «сжатие с каждым ключевым узлом».
- **Толмач.** После ключевых узлов миссии — приказ совета принят, вход исполнен, добор, решение
  перепроверки, ответ FLASH у троса, закрытие (тейк / стоп / CLOSE / паника), стопор «рынок закрыт /
  открылся», отказ биржи с текстом ошибки — FLASH пишет владельцу 3–7 живых предложений: что произошло,
  почему (цена, уровни, новости, совет), что пилот делает дальше, за чем следить. Не чаще раза в 20 с —
  узлы за окно объединяются в одно объяснение; тот же отказ биржи подряд не повторяется. Сбой FLASH —
  честная заглушка «толмач не ответил», миссия не страдает. На экране миссии — карточка **«Что
  происходит»** (лента со значками по виду узла, свежая запись подсвечена, приходит готовой по шине);
  у карточки «Приказ» — отметка «обновлено HH:MM», при новом приказе изменившиеся поля (сторона, вход,
  тейк, стоп) подсвечиваются, а если уровни те же — так и сказано.
- **Память миссии.** После каждого совета, после закрытия позиции и раз в `PYTHIA_MEMORY_EVERY`
  перепроверок FLASH сводит накопившееся (старые перепроверки, передачи, ответы у троса, объяснения
  толмача, сделки, новости старше последнего совета) в один связный абзац ≤ 1 500 символов «что было и
  чем кончилось» с датами; сырые списки после этого режутся (остаются 5 перепроверок, 3 ответа у троса,
  5 передач, 10 объяснений), критичное (позиция, уровни, приказ, сделки) не сжимается. Блок «ПАМЯТЬ
  МИССИИ» видят аналитик, критик, вердикт, перепроверка, трос и чат; перепроверка и трос получают только
  новости после совета — старые живут в памяти. На экране — сворачиваемый блок «Память миссии».
- API: `GET /api/v5/mission/explain?ticker=` → `{items, memory, enabled, model, pending}`;
  `status()["explain"]`, `status()["memory"]`, `status()["exec_ts"]`.

## Что показывает панель при проблемах

`GET /api/v5/state` отдаёт блок `health` — список проблем человеческим языком: что случилось и что нажать.
Нет ключа DeepSeek или токена Tinkoff → «нажми «Ключи» в шапке»; последняя ошибка DeepSeek (401 — ключ не
принят, 402 — баланс, 429 — лимит, таймаут/сеть) с временем и маршрутом, пока ИИ не ответил снова; последняя
ошибка биржи текстом Tinkoff (30042 и т. п.); рынок закрыт (до какого времени; пилот в стопоре); небо в
lite-режиме (нет эфемерид); Telegram (kind `telegram`: токен есть, чат не привязан — info; бот отбит 401/403/сеть —
warn; в шапке пилюля «Telegram» — нет токена / не привязан (жёлтая) / ошибка (красная) / подключён, та же строка в
пузыре состояния на телефоне и внизу списка проблем); пилот — трос на бирже не встал, закрытие отбито, killswitch, бэкофф после отказов
биржи; протухшие данные — цена миссии старше минуты при открытом рынке или пустой стакан. Уровни: `err`
(без этого не работает), `warn` (работает хуже), `info` (норма, но знать надо: сухой прогон, мок, рынок
закрыт). Сбой любого источника не роняет состояние — блок просто короче. Рядом: `last_ai_error`,
`last_broker_error`, `astro_mode`, `ws_clients`, `state_age_s` (секунд с последнего тика пилота).

## Проблемы и свежесть

В шапке живёт индикатор **«Проблемы»** — счётчик и цвет по худшему уровню (красный `err`, янтарный `warn`,
индиго «к сведению», зелёный «Порядок»); нажатие раскрывает список: значок по источнику, текст человеку, время
и кнопка действия («Ключи», «К миссии», «Повторить», «Переподключить», «Обновить», «Дозор сейчас», «Скрыть»).
В списке — серверный `health` плюс то, что видит сама панель: сервер недоступен (тот же баннер под шапкой),
поток `/ws/events` оборван (с отсчётом до переподключения), запрос API упал (код и `note` сервера — и в тост,
и в запись; пропадает, когда тот же запрос прошёл), снимок состояния старше 15 с при живом потоке, цена миссии
старше минуты при открытом рынке, сканер «идёт», но тики не приходят, дозор пропустил цикл, нет ключей, рынок
закрыт. Внизу — последние ошибки DeepSeek/Tinkoff, если ИИ и биржа потом ответили (тускло, не как проблема).
Тосты об ошибках висят до «×» или пока не исправилось (тот же путь ответил); повтор одной и той же ошибки не
плодит тосты, а вспыхивает. Ошибка стадии в степпере раскрывается текстом и предлагает действие («Повторить
совет», «Повторить взгляд», «Пересмотр миссии», «Продолжить пилот»); отказ биржи в ленте толмача — с красной
каймой. Свежесть: у итога совета и карточек идей, приказа миссии, решения PRO, памяти миссии — «обновлено
HH:MM» и бейдж «устарело» по порогу (совет 6 ч, приказ 2 ч = `EXEC_FRESH_SEC`, перепроверка — два периода,
память — сутки); сканер «стоит · устарело», дозор «пропустил цикл». Новый итог совета или новый вердикт
миссии подсвечивает карточку и прокручивает к ней, если экран открыт, иначе вешает «новое» на вкладку.
Хроника пилота — разрезы «все · решения PRO · FLASH · поводы», соседние триажи событий собраны в одну строку,
длинный список — «ещё N». Все кнопки панели запираются на время запроса и показывают ответ сервера; 409/400 —
понятным текстом; форма ключей проверяет вставленное до отправки; чат честно сообщает «сети нет» / «ИИ занят»
и возвращает текст в поле.

## Панель миссии: что где (v5.3 фаза 3, W3)

Экран миссии выстроен по важности. Сверху карточка **«Сейчас»**: позиция крупно (сторона, лоты, вход,
плавающий P/L цветом), триггер · трос биржи · тейк с расстояниями в % от живой цены (плитка подсвечивается,
когда цена ближе 0,35 %), отсчёт до перепроверки с поводом, статус биржи; без позиции — что ждём (план входа,
заявка, приказ, стоп пилота). Ниже **«Что происходит»** — свежее объяснение толмача крупно с чипом модели
(FLASH бирюзовый, PRO индиго), остальные лентой. Дальше приказ, рамка, пилот (отсчёт, итог, депозит, счёт,
триггер/трос), сканер с блоком **«Прокол»** (кольцо стойкости против порога, роль цветом — за нас зелёный,
против янтарь — и цепочка «ИИ дали → FLASH-триаж → PRO решил» или причина тишины), **«Связанные бумаги»**
(ρ полоской со знаком, ход дня и 5 дней, цена, «опережает/отстаёт на день»; пусто — почему), кресла совета
(свёрнуты, пока есть свежее объяснение толмача, «развернуть все» — руками), «Что видел ИИ», график, сделки.
Пузырь токенов в шапке — по моделям (доля FLASH/PRO) и по маршрутам с понятными именами (стоимость не
считается — тарифов панель не знает). Цвета ролей едины: FLASH — бирюза, PRO — индиго, совет — янтарь,
биржа — зелёный/красный; числа табличные с разрядами; анимации уважают `prefers-reduced-motion`; на телефоне
плитки в две колонки, таблицы — карточками, без горизонтальной прокрутки.

## Проверка

```
python3 -m compileall -q backend
for m in ai_v5 bus store_v5 compress newsflow council watch mission market_ctx market_clock ai_pilot trader_broker mock_ai prompts_council prompts_mission api_council api_mission api_chat api_v5 scout correlate explain astro maya_scan scenarios tinkoff ledger telegram; do python3 -m backend.$m; done
```
Self-тесты не оставляют следов в `data/` (ключи, state-файл, аудит, базы — на временных путях; сам импорт
`store_v5` создаёт базу, если её нет, и временные WAL/SHM).

**Регрессионные тесты (два прохода стороннего ревью 24.09.2026 + наши).** `pip install -r requirements-dev.txt` (pytest;
самому терминалу не нужен), затем `python3 -m pytest tests -q` — регрессии (×308: 233 в 5.4.0 + 5.4.1: `tests/test_settings_api.py` — переключатели пилота через
`/api/v5/keys`, `tests/test_pilot_541.py` — проверка входа, мысль о прибыли, стопы в программе, `tests/test_prompts_voice.py` —
голос промптов): сохранность базы при ошибках старта и
повреждении (повреждённая откладывается в `.broken-<время>`, заблокированная — стоп с сообщением), миграция, атомарная
вставка новостей, ключи и сумма миссии, гонки запусков совета/дозора, порядок остановки служб, исполнение заявок и
восстановление после сбоя (потерянный ответ, частичные исполнения, отмены, стоп-запросы, паника, force), журнал по
операциям, форма запросов к DeepSeek и узлы у денег; `node --test tests/test_frontend.cjs` — 18 проверок кода панели
(`index.html`: поздние ответы свечей/статуса/цены/сделок, склейка опросов и полных обновлений состояния, защита от позднего
опроса миссии, разбор всего скрипта, поиск, отказ запуска, чат). Node нужен только для них. Стенд биржевых ситуаций —
`python3 -m backend.scenarios`: 41 сцена: 31 из 5.4.0 + 9 в 5.4.1 (проверка входа у двери, мысль о прибыли, стопы в программе, приказ WAIT) + 1 в 5.4.2 (совет «держать» — приказ HOLD без добора).
Контракт модулей и API — `docs/ARCHITECTURE_V5.md`; карта ИИ-вызовов (кто, когда, модель, таймаут, цена) —
`docs/ИИ_ВЫЗОВЫ.md`; инструкция владельцу —
`docs_ЗАПУСК_V5.txt`; журнал проекта — `NEXT_CHAT.md`.

**Стенд ситуаций.** `python3 -m backend.scenarios` прогоняет настоящую миссию и пилот (перепроверка PRO,
FLASH у троса и у тейка, триаж, совет, толмач, журнал сделок) через 25 биржевых ситуаций на фейковой бирже и
фейковом ИИ — без сети и ключей: гэп за аварийный трос и за триггер, мёртвый рынок (нет котировок, стакан
протух), рынок закрылся и открылся, частичное исполнение и отказ 30042, резкий ход с триажем, мягкий тейк
(зафиксировать / подержать → совет / FLASH молчит / запертая прибыль при откате), шквал новостей, рестарт
сервера в позиции, докупил/продал/перевернул руками, CLOSE при заявке в полёте, дневной killswitch,
молчание FLASH/PRO, отбитая стоп-заявка, переворот при молодой позиции, добор при нуле от биржи, два
закрытия разом, триаж событий (ПЛАНОВО / САМ / молчит / СЕЙЧАС), прокол сканера (в сторону плана → PRO с блоком
ПРОКОЛ СКАНЕРА и вход; против позиции → триаж, дедуп, САМ подтянул трос; ниже порога / без плана / выкл — тишина). В таблице по каждому сценарию: ордера, вызовы ИИ (FLASH/PRO по маршрутам), последнее
